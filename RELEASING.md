## Attached binaries versus autogenerated source archives

For Windows installation, download the **version-specific attached x64 ZIP** from the Releases page and keep its matched DLL and controller together. Autogenerated `Source code (zip/tar.gz)` files contain **source only**, not an installable Windows binary package.

Each release's asset names, SHA-256 digests, direct links and version features are indexed in [SCRATCH_RELEASES.md](SCRATCH_RELEASES.md). Do not replace attached ZIPs merely to change release source tags or documentation.

## Packaging, testing and upgrades

1. Build the Scratch controller and VST DLL together from the same source version.
2. Run the offline DSP tests and static analysis, then validate on Windows with Equalizer APO.
3. Archive the complete matched x64 DLL, EXE, sources, instructions and tests as one release asset.
4. For a new Scratch version, create a unique `scratch-v...` tag **on that version's source commit**. Never tag the lightweight `main` source for a Scratch release.
5. Keep earlier release attachments and their source tags immutable after publication whenever possible.
6. For upgrades, close the previous Scratch controller before extracting the new folder. Do not interchange controller EXEs and DLLs from different versions.

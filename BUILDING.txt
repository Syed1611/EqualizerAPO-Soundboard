Rebuilding APO Soundboard x64
==============================

The source deliberately has no JUCE, Visual C++ runtime, Steinberg SDK, or other binary
dependency. It implements only the small VST2 ABI subset that Equalizer APO uses.

Required:
- LLVM clang targeting x86_64-pc-windows-msvc
- lld-link

From the src directory:

clang -target x86_64-pc-windows-msvc -O2 -ffreestanding -fno-stack-protector -fno-builtin -c plugin.c -o plugin.obj
lld-link /dll /subsystem:windows /entry:DllMain /nodefaultlib /machine:x64 /export:VSTPluginMain /out:APOSoundboard.dll plugin.obj

clang -target x86_64-pc-windows-msvc -O2 -ffreestanding -fno-stack-protector -fno-builtin -c controller.c -o controller.obj
lld-link /subsystem:windows /entry:entry /nodefaultlib /machine:x64 /out:APOSoundboardController.exe controller.obj

Static checks:
file APOSoundboard.dll APOSoundboardController.exe
llvm-objdump -p APOSoundboard.dll

Expected:
- Both files are PE32+ x86-64.
- DLL export table contains VSTPluginMain.

Design notes
------------
The binaries intentionally use a tiny Win32 runtime resolver in winlite.h, so they do
not require a separately installed MSVC redistributable. APOSoundboard.dll exposes a
2-input/2-output replacing VST2 effect. Mono Equalizer APO capture configurations still
work because Equalizer APO supplies an empty second channel and uses the first output.
